# Debug log

Notable bugs found while building and testing, with root cause and fix.

| # | Phase | Symptom | Root cause | Fix |
|---|-------|---------|------------|-----|
| 1 | P1 | Synthetic fail rate was 22%, not the ~10% the spec asks for | Score intercept too low for the variance of the latent skill | Calibrated the intercept (57 → 66) against measured fail rates; now 10.6% |
| 2 | P1 | `MST (2)` would have been read as "max marks = 2" and the header stripped to `MST` | Max-mark hint regex accepted any number in brackets | Hints only count from 5 to 1000 marks, and are only stripped from the name when they count |
| 3 | P1 | `test_write_sample_files` failed on `co_mapping.csv` (82 bytes) | Test assumed every file > 100 bytes; the CO map is legitimately 6 short rows | Test now checks real content (row counts) instead of an arbitrary size |
| 4 | P2 | Every CO attainment call crashed with "truth value of a Series is ambiguous" | Operator precedence: `a \| b \| c.any()` applied `.any()` to the last term only | Build the full mask first, then call `.any()`; added a regression test for a blank / missing CO |
| 5 | P3 | 40% of student-subjects showed as "declined" from MST-1 to MST-2 | With MSTs out of 15, one mark = 6.7 percentage points, so a 5-point tolerance flagged every one-mark dip | Default tolerance raised to 10 points (1.5 marks); declines now match the genuine large drops in the data (216 vs 216) |
| 6 | P3 | Clicking a bar highlighted it in the browser but the drill-down never happened | A per-bar `marker.opacity` array combined with text labels stops Plotly from emitting the selection event (each alone is fine — found by bisecting in a headless browser) | Highlight the drilled bar with a per-bar colour array instead of opacity |
| 7 | P3 | Clicking a heatmap cell did nothing | Plotly heatmaps emit no selection events in Streamlit at all (confirmed with a minimal app) | An invisible square marker sits on every heatmap cell; it catches the click and carries the tooltip |
| 8 | P3 | Lambdas for chart callbacks would all have read the last chart's state | Python late binding: each lambda captured the loop variable `key`, reassigned for the next chart | Callbacks bound with `functools.partial` |
| 9 | P3 | A corrupt `.xlsx` upload crashed the whole app | The sidebar's sheet lookup ran before the main area's `try/except LoadError` | Sidebar catches `LoadError`; the main area shows the friendly message (AppTest regression test added) |
| 10 | P4 | AI results that were sorted showed an extra `index` column of jumbled row numbers | The sandbox turned *any* non-RangeIndex into a column, including the leftover integer index after `sort_values` (found by the HTTP integration test) | Only named, multi-level or non-integer indexes become columns; plain row numbers are dropped. Regression tests added |
| 11 | P4 | LLM client tests failed to import `httpx` | openai 3.x ships its HTTP layer as `httpx2` | Tests import `httpx2`, falling back to `httpx` for older SDKs |
| 12 | P4 | Charts the AI drew used Plotly's default purple, clashing with the dashboard | `px` picks colours from its default template inside the sandbox | The app passes its palette and font to the sandbox, which installs them as the default Plotly template |
| 13 | P4 | Base64 `bdata` arrays in AI figures could be corrupted when swapping IDs for names | Plotly 7 encodes numbers as base64 strings, which can contain text like `S123` | Unmasking skips `bdata` keys; test checks numeric data survives byte-for-byte |
| 14 | P5 | At-risk reasons read "MST-2 dropped vs MST-1 in nan (-7 pts)" for students with no real drop | pandas pitfall: assigning a Series to an *empty* filtered frame adopts the Series' index, turning "no rows" into NaN rows | Rules rewritten to filter after computing; regression test `test_small_dip_is_not_a_reason` |
| 15 | P5 | 116 of 180 sample students (64%) flagged at risk | One MST dip of 1.5 marks was common (73% of students) and scored points; single weak signals reached Medium | Recalibrated: only drops of 20+ points count; one signal alone is Low; a failed subject is Medium. Now 81 by rules (55 students actually failed a subject) |
| 16 | P5 | Rule scoring took 1.5 s for 180 students | A Python loop with several pandas operations per student | Vectorised per-row flags, one grouped pass, reasons built from plain dicts: 0.06 s (25x faster); test asserts 1,080 students < 2 s |
| 17 | P5 | With the model on, nearly every student who failed a subject became High risk | The model "predicted" fails that had already happened (out-of-fold probability ≈ 1) | The model only scores subjects not already failed: it flags the *next* likely fail |
| 18 | P5 | Mid-semester rows showed "Failed Python" before any end-term exam | Results are projected from internals mid-semester; the rules treated a projected Fail as real | A fail counts only when final marks (total or end-term absence) exist; otherwise it is "internal marks below pass" |
| 19 | P5 | Students below the pass mark were also called "borderline" | Borderline was defined as "under pass + 10" | Borderline now means passing by less than 10 points (40-50% with the default pass mark) |
| 20 | P5 | Out-of-fold probabilities could attach to the wrong students if row order changed | They were keyed by the DataFrame's positional index | Keyed by (roll_no, subject); test checks a filtered, reversed view gets identical values |
| 21 | P5 | Training took ~4 s | Each model was fitted twice per fold (once for scores, once for probabilities) | One fit per fold yields both: ~2 s |
| 22 | P5 | Profile charts: attendance labels collided with the requirement line; radar clipped "Computer Networks" | Labels outside bars sat on the dashed line; radar margins too narrow | Labels inside bars, annotation top-left; wider radar margins |
| 23 | P6 | Report tests could not import `pypdf` | It was installed system-wide, not in the project environment | Added to the dev requirements and installed in the venv |
| 24 | P6 | Excel header fill was written as lowercase hex (`002a78d6`) | Palette colours are lowercase; openpyxl stores them as given | Colours are upper-cased before use (Excel's own convention) |
| 25 | P6 | In the PDF's CO chart, the "Target" label overlapped the last bar's label | The label was drawn at the right end of the target line, where bar labels also sit | The target line is described in a legend under the chart |
| 26 | P6 | Header and risk-level cells in PDF tables ignored their colours | ReportLab parses a Paragraph's style when it is created; changing `.style` later has no effect | Styles are passed when each Paragraph is built |
| 27 | P6 | Summary said "CO3 fall below the target" | Plural verb for a single CO | Verb agrees with the number of COs |
| 28 | P7 | In a non-root run, asking the AI crashed the whole page with `PermissionError` | Creating the OpenAI client read an unreadable CA bundle (`SSL_CERT_FILE`); the error escaped as a raw exception | Client setup errors (`OSError`, `ValueError`) become a friendly `LLMError` shown in the chat; regression test added |
| 29 | P7 | Tests that need "no AI key" could pass a developer's own `.env` key through | `load_dotenv` at startup refills variables the test had deleted | Tests set the variables to empty strings; `load_dotenv` never overrides existing variables |
| 30 | P8 | The 1,000-student report test failed under coverage (16.6 s, limit 10 s) | ~112,000 per-cell style assignments in the Excel writer (a border and number format on every data cell); openpyxl hashes each style object | No per-cell borders on data rows; the large Cleaned Data sheet is rounded and bulk-appended instead of styled cell by cell. Excel build 5x faster (≈2 s for 1,080 students) |
| 31 | P8 | On a phone the sidebar covered the whole screen at start-up | `initial_sidebar_state="expanded"` forces it open at every width | `"auto"`: open on desktops, collapsed behind » on phones |
| 32 | P8 | Sandbox review: `fig.to_image()` could spawn an external renderer | Image export was not on the blocked list | `to_image` and `full_figure_for_development` blocked; more escape tests (f-string dunder, `__builtins__`, subclass walk, bare file path as a SQL table) |
| 33 | P8 | Testing the shipped zip in a fresh environment skipped the `.xls` upload test | Its fixture writer (`xlwt`) was installed locally but missing from `requirements-dev.txt`, and `importorskip` hid that | `xlwt` pinned in the dev requirements; the test now imports it directly so a missing dependency fails loudly |

### Bug hunt, round 3 (multi-step sessions, 5,000-student scale, deployment in a real container)

| # | Area | Symptom | Root cause | Fix |
|---|------|---------|------------|-----|
| 53 | **Speed** | **With 5,000 students, every filter change waited ~6 s for risk scores** (the KPI card is recomputed on each change) | For each flagged student the model explanation built a one-row DataFrame, and levels were combined with a row-wise `DataFrame.apply` | Features for all flagged students in one pass; explanations and levels from plain arrays. 6.1 s → 0.33 s, output verified identical (levels, scores, probabilities, every reason string) on five datasets |
| 54 | **Memory** | **The Excel report for 5,000 students × 8 subjects took 9.8 s and +258 MB** — enough to push a 1 GB host over the edge on top of the app's ~470 MB | openpyxl kept ~760,000 Cell objects in memory and serialised them with its pure-Python XML writer | Workbook written in openpyxl's streaming write-only mode, values converted per column, `lxml` added so openpyxl uses its C writer: 5.1 s and +22 MB. The executive summary is one sentence per line (write-only sheets cannot merge cells) |
| 55 | Speed | Moving the pass-mark slider on a 5,000-student sheet took 11.8 s (retraining) | The model was cross-validated on all 40,000 rows, twice per fold count | Training uses a stratified sample of up to 10,000 rows (4 features saturate far earlier); rows outside the sample get genuinely out-of-sample predictions. 11.8 s → 4.4 s; first load 10.4 s → 4.3 s. The At-Risk tab says when a sample was used |
| 56 | **Deploy** | **On Hugging Face Spaces every file upload would fail with 403** | Spaces shows the app in an iframe on huggingface.co; browsers block Streamlit's XSRF cookie there. Reproduced in Chromium with the app embedded cross-site: upload HTTP 403 | The container adds `--server.enableXsrfProtection=false` only when `SPACE_ID` (set by Spaces) is present: upload HTTP 204. XSRF stays on everywhere else |
| 57 | Deploy | `COPY --chown=appuser:appuser` would fail on bases whose `useradd` does not create a same-named group | Group creation is a distro default (`USERGROUPS_ENAB` in login.defs) | `groupadd` + `useradd --gid` explicitly |
| 58 | Deploy | The container polled its own source files for changes forever | No `watchdog` in the image, so Streamlit fell back to a polling file watcher | `STREAMLIT_SERVER_FILE_WATCHER_TYPE=none` in the image (local `run.sh` keeps live reload) |
| 59 | **Memory** | **Exploring the sliders on a 5,000-student sheet grew the server from 373 MB to 746 MB and kept climbing** (a 1 GB host would be killed) | Cleaning and derived columns were cached under the *whole* settings object, so every pass-mark or attendance move stored another full copy; caches allowed up to 32 entries and never expired | Each step is keyed only on the settings it reads (cleaning: max marks; derived columns: max marks + pass mark); entry caps lowered (derive 32 → 8, prepare 16 → 6, risk 16 → 8, raw sheets 8 → 4) and one-hour expiry added. Same sweep now plateaus at ~545 MB |
| 60 | **Filters** | **In a real browser, "Reset filters" and uploading a new sheet did not clear the filters**: the box still showed "Section B", the numbers briefly showed everyone, and the next click silently re-applied Section B. AppTest could not see it (it does not keep browser widget state) | Resets *deleted* widget keys from session state. That resets the server's copy only; the browser keeps the old value and sends it back | One table of widget defaults, reset by *assignment* (the supported way). Widgets that set their own `default=`/`value=` are initialised from session state instead. Re-verified in Chromium: filter cleared and stays cleared after further clicks |
| 61 | AI chat | A question interrupted by another click (a new question, a filter or tab change) stayed in the chat with no answer and no explanation | Any widget interaction reruns the script and stops the agent mid-way | A trailing unanswered question is marked "Stopped before finishing" with an **Ask again** button. Verified in Chromium |
| 62 | **PDF** | **Student names, college or title in Hindi, Punjabi, Tamil, Bengali or any other Indian script printed as empty boxes in the PDF report** (and in its charts) | The PDF used DejaVu Sans only, which has no Indian-script glyphs. Two further traps found on the way: ReportLab shapes a whole word with the font of its first piece, so "मीरा," turned the comma into "Ή" and "(क)" lost its letter; and conjuncts/vowel signs need HarfBuzz shaping | Noto fonts for nine scripts (Devanagari, Bengali, Gurmukhi, Gujarati, Odia, Tamil, Telugu, Kannada, Malayalam; 2.9 MB, OFL) bundled; text split into per-script font runs; `uharfbuzz` added for shaping; each same-font stretch of a word shaped separately. Verified visually for all nine scripts in the title, cover, summary, tables, footer and chart labels; tests check the embedded fonts and that punctuation keeps its glyphs |

Known limits after round 3: chart labels in Indian scripts show the right letters but are not shaped (matplotlib has no shaping), so a conjunct may appear as its parts; text copied out of the PDF loses some conjuncts (they are drawn as ligature glyphs); right-to-left scripts (Urdu) are not supported.
